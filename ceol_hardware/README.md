# ceol_hardware

## 1) Overview

`ceol_hardware` provides the live `ros2_control` hardware plugin for the Ceol platform.

It specializes the generic `2THD` continuous-track hardware abstraction from `romea_mobile_base_hardware` and connects the Ceol low-level controller to the ROS 2 control stack through SocketCAN.

The plugin centralizes the communication with the parts of the robot available on the CAN bus:

* mobile base commands and feedback, exposed through the `2THD` `ros2_control` command and state interfaces and controlled from the skid-steering command model;
* embedded inertial measurement unit feedback, republished as ROS 2 IMU measurements;
* rear three-point hitch commands, currently received through an implement command topic while the future `romea_implement_hardware` package and the dedicated controller are still planned.

With the usual `ceol_base` hardware name, the topics are:

| Topic | Direction | Message |
|---|---|---|
| `/ceol/base/imu/data` | published by the hardware plugin | `sensor_msgs/msg/Imu` |
| `/ceol/base/implement/rear/command` | subscribed by the hardware plugin | `romea_implement_msgs/msg/Command` |

The exported plugin is:

| Plugin | Base class | Mobile base architecture |
|---|---|---|
| `ceol_hardware/CeolHardware` | `HardwareSystemInterface2THD` | `2THD` |

## 2) Hardware concept

`CeolHardware` is loaded by `controller_manager` from the `<ros2_control>` description generated by `ceol_description`.

At runtime, `CeolHardware`:

1. reads the Ceol `ros2_control` hardware information;
2. creates the `HardwareInterface2THD` command and state interface mapping;
3. loads the sprocket wheel and track parameters required to convert angular commands into track motion;
4. opens CAN communication on `can0`;
5. starts a receiver thread for Ceol feedback frames;
6. converts controller commands into Ceol CAN frames;
7. receives rear three-point hitch commands from the implement command topic;
8. converts hitch commands into Ceol CAN frames;
9. converts mobile base CAN feedback into `ros2_control` state interfaces;
10. publishes IMU feedback received from the robot.

From the controller point of view, this behaves like a standard mobile base hardware plugin: `romea_mobile_base_controllers/MobileBaseEnhancedController2TD` writes left and right sprocket wheel commands to command interfaces, then reads feedback from state interfaces and IMU feedback to compute odometry.

## 3) CAN communication

The hardware plugin sends commands for:

* left and right sprocket wheel speed commands;
* rear three-point hitch actuator position commands;
* null commands when the interface is activated, deactivated or disconnected;
* low-level control frames required by the Ceol controller, including auto-mode and NMT frames.

It receives feedback for:

* left and right sprocket wheel speed and torque measurements;
* rear three-point hitch actuator positions;
* IMU linear acceleration and angular velocity measurements;
* low-level status information, including auto-mode authorization.

The current implementation uses the `can0` SocketCAN interface. Since the mobile base, IMU and rear three-point hitch share this bus, the intended architecture is to keep a single `ceol_hardware/CeolHardware` plugin for the shared CAN communication layer. Inside this plugin, the mobile base part relies on `romea_mobile_base_hardware`, while the hitch part is expected to rely on a future `romea_implement_hardware` abstraction dedicated to three-point hitch control. The low-level CAN hooks for the hitch actuators are already present, but the reusable implement hardware abstraction and the dedicated ROS 2 controller are not provided yet.

## 4) Relation with other packages

`ceol_hardware` is the live hardware specialization of the Ceol mobile base:

* `ceol_description` selects `ceol_hardware/CeolHardware` in `live` mode;
* `romea_mobile_base_hardware` provides the reusable `2THD` hardware abstraction;
* `romea_mobile_base_utils` provides helpers used to read `hardware_interface::HardwareInfo`;
* `romea_mobile_base_controllers` sends commands through the exported `ros2_control` interfaces;
* `ceol_bringup` starts the controller manager and loads this hardware plugin in live mode.
